v1.1.3  (2026-10-22)  THE fix: run the message loop through PowerShell
  Fixed   : User Lookup's "Object reference not set" was NOT the AD query (your
            snippet returned 588). The stack showed a NullReferenceException in
            SuspendStoppingPipeline when a button handler's try/catch/finally ran
            with no PowerShell pipeline on the event thread. The host now runs the
            WinForms message loop THROUGH the runspace (like the source tool), so a
            pipeline is always active and try/catch in any handler works. Refresh,
            Copy, Export and every ported admin action depend on this.
  Fixed   : Shimmed Add-ActivityLogLine (display-only in the original) so the
            Directory tab stops logging "term not recognized". The grids/tree work
            without it; the Activity pane needs the full logging module (later).

v1.1.2  (2026-10-22)  User Lookup: match the original's proven query; real errors
  Fixed   : Removed the pre-bind check ($root.NativeObject) added in 1.1.1 - that
            was the actual source of the null-reference. The query now matches the
            ORIGINAL tool exactly: a plain DirectorySearcher against the current
            domain (what works on your machine). A configured Server is tried
            first and falls back to the current domain on any failure.
  Changed : Any failure now writes the FULL exception (type, base cause, stack) to
            Session.log and the dialog shows the real root cause - no more bare
            "Object reference not set". One bad record no longer aborts the load.

v1.1.1  (2026-10-22)  Fix User Lookup "Object reference not set" on query
  Fixed   : The query bound to the active environment's Server, and the shipped
            default Server was a sample domain (AERAIPCS.COM) this machine is not
            on - the failed LDAP bind surfaced as a null-reference error. The bind
            now happens up front (clean error), and if a configured Server cannot
            connect the query falls back to the current domain.
  Changed : Default environment is now "Current Domain" with a BLANK Server, so
            out of the box the lookup queries the domain this machine is joined to.
            The AERAIPCS.COM / CA1-OG.ADS entries remain as clearly-marked examples.
  Changed : Clearer AD error message (names the active Server and what to check).

v1.1.0  (2026-10-22)  Port areas 1 and 2: Password Generator + Directory
  Added   : Tools tab now hosts the real Password Generator (ADTools_Password-
            Generator_*). Generate, Copy, and the editable Phrase/Symbol/Number
            word lists all work; no AD connection needed. Word lists live in the
            data root's Config\PasswordGenerator.json.
  Added   : Directory tab now hosts the real Users/Groups/Activity panes plus the
            shared OU tree (ADDirectory_* + the AD query/reporting services).
            Needs the RSAT ActiveDirectory module and a reachable domain; it
            connects to the active domain's Server (Defaults tab), else the
            current domain. If not connected, a banner says so and User Lookup
            still works.
  Added   : Shared-scope loader. The original app dot-sourced all modules into one
            $script: scope; the template imports modules in isolation. So the
            launcher now COMBINES the ported AD modules into one module ("ADTool")
            and imports that once, preserving their cross-file shared state, while
            the template's own modules stay isolated. AD_Core builds a faithful
            $Context from $App and shims the launcher helpers the AD modules call
            (Set-Status, Set-Selected*, Write-OperationLog, Get-OperationLog).
  Note    : The fixed-size AD layout is wrapped in an AutoScroll panel, so on a
            smaller window it scrolls rather than clips (maximize for best fit).
            Directory context-menu ACTIONS that call not-yet-ported areas (User
            Actions: reset/offboard) may be inert until those areas are ported.
  Note    : Untested here (no Windows/AD/compiler on my side). Build and test on a
            domain-joined machine; errors surface in-tab and in Session.log -
            paste them back and I will fix. Areas still scaffolded: Infrastructure,
            Audit, Bulk Ops, Computers, User Actions.
