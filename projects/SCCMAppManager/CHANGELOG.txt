# CHANGELOG.txt -- project version history (newest first)
# Each update package carries this file with its new section on top, plus the
# bumped VERSION.txt, so Version History and the archived EXEs line up.

v1.0.7 (2026-11-02)  Engine synced v1.0.16 -> v1.0.20 (AppTemplate)
  Changed : Template-owned files replaced with AppTemplate v1.0.20 (manual sync: the
            v1.0.17 step is a contract change). TEMPLATE_FILES.txt and
            TEMPLATE_VERSION.txt copied from the template.
  Changed : Project identity moved from the PROJECT IDENTITY block in AppHost.cs to
            AppIdentity.json (SCCM App Manager / SCCMAppManager / SCCMAppManager).
            Same AppDataFolder, so saved environments, settings and logs are kept.
  Added   : From the template: Update Template button, Build Lite button, Update folder,
            Open menu (App folder / Logs / AppData), Build-App.cs + Build-App.cmd (build
            without PowerShell), machine facts on the Session.log start line,
            Services_Filter.psm1 and Services_Requirements.psm1 (available to tabs).
  Removed : Function Map and Environment buttons (both files are in every Extract and
            Archive zip).
  Note    : No project module changes. Later 1.0.x engine updates go through Update Template.

v1.0.6 (2026-10-26)  Tabs load on first view without Refresh
  Fixed   : Devices (and the other SCCM tabs) could stay empty on first view until Refresh:
            their load depended on the tab-changed event, which did not start it. Each tab now
            starts its own load right after it is built (and still waits for a running
            operation to finish first).
  Added   : Session.log DIAG line "Tab load: <tab>" (with diagnostics on) when a tab load runs.

v1.0.5 (2026-10-26)  Tabs opened during a load fill themselves afterwards
  Fixed   : A tab selected while another operation was running (for example Devices during
            the startup scan / connect) skipped its load and stayed empty until Refresh. It
            now waits and loads as soon as the running operation finishes, if still shown.

v1.0.4 (2026-10-26)  Connect automatically at startup
  Fixed   : At startup the Update Pipeline tab could stay "not connected" and the Devices tab
            did not load until Refresh. One failed connection attempt blocked all automatic
            loading for that environment; now it only waits 30 seconds, then tab visits retry.
  Fixed   : The tab shown about 1 second after launch is always loaded, even if its first
            selection happened before the loader was ready.
  Changed : A ConfigurationManager module import that reports an error but still loads the
            module (seen on some consoles) is accepted with a warning instead of failing.

v1.0.3 (2026-10-26)  Name filter with wildcards
  Changed : Every filter box (Software, Collections, Devices, pickers, detail windows, Add
            Devices) now matches the FIRST column only: application, collection or device name.
  Added   : * and ? wildcards anywhere in the filter (contains, case-insensitive), e.g.
            ivn-*-ic matches IVN-1234-IC. Text without wildcards filters as before.
  Fixed   : Changing the selection no longer re-runs the filter (count label only).

v1.0.2 (2026-10-26)  Reload data every time a tab is selected
  Added   : Update Pipeline, Software, Collections and Devices reload from SCCM each time
            their tab is selected (Pipeline also rescans the JSON files). Skipped when the data
            was loaded in the last 5 seconds. Devices reloads devices + memberships too.
  Added   : Environment > SCCM Site: "Reload data every time a tab is selected" (on by
            default). Off = load once per environment, then Refresh / F5 - as in v1.0.1.
  Note    : Includes the v1.0.1 grid fix (SAM_Grid.psm1), so it also applies on v1.0.0.

v1.0.1 (2026-10-26)  Fix: grid error dialog on Show members
  Fixed   : Show members (and any grid reloaded while open) could raise "DataGridView Default
            Error Dialog - Index n does not have a value". Grids are now detached from their
            table while it is refilled; the header sort arrow is restored afterwards.
  Added   : Grid data errors are written to the activity log instead of a dialog.

v1.0.0 (2026-10-26)  SCCM App Manager - created from AppTemplate v1.0.16
  Note    : Rebuild of SCCM_App_Lifecycle_Manager.ps1 v8.4 on AppTemplate v1.0.16.
            Identity: SCCM App Manager / SCCMAppManager.exe / %LOCALAPPDATA%\SCCMAppManager.
  Added   : Multi-site. One environment = one SCCM site (A30, CA1). Per-site settings
            on Environment > SCCM Site (site code, SMS Provider, Local Root, Incoming,
            Repository, Icons, test collection, DP group, robocopy threads, prune),
            with Test connection and Detect server. Blank fields fall back to the v8
            settings file (%APPDATA%\SCCMAppManager\settings.json) for the same site.
  Added   : Update Pipeline tab - the v8.4 pipeline (scan, pull, update JSON, upload,
            create, deploy, newer-version gate, PERF timing) plus a right-click menu,
            a JSON file column and an activity log pane.
  Added   : Site-tagged JSON. Exports write "SiteCode" and <AppBaseName>_<SITE>.json;
            the pipeline shows the active site's JSON files (and untagged ones).
  Added   : Copy JSON to environment - makes another site's JSON from the selected
            rows with repository / content / icon / command paths re-pointed, every
            change shown in the review dialog first.
  Added   : Software tab - every application with deployments, targeted, installed,
            in progress, failed, requirements not met and unknown counts. Right-click:
            deploy, deployments, device install status, export to JSON, distribute /
            update content, copy names.
  Added   : Collections tab - every collection with member and deployment counts.
            Double-click: members with install status. Right-click: add devices,
            deploy software to the collection, deployments, update membership.
  Added   : Devices tab - every device with collection and targeted-deployment counts.
            Multi-select + right-click "Add to collection..." (direct members, WMI
            first, ConfigMgr cmdlet as fallback).
  Added   : Admin tier - remove members, delete deployments, retire / reinstate /
            delete applications, new / rename / delete collections, delete device
            records, clear PXE deployments. Every SCCM change goes to the
            environment's action log.
  Changed : All lists show everything by default (no folder / collection pre-filter);
            filter as you type, header-click sorting, Export CSV on every grid.
  Changed : Logging follows the template: Session.log + <environment>.log in the data
            root; PERF timings in Logs\perf.csv; robocopy logs in Logs\Robocopy.
